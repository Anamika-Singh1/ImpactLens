# Case study: making release impact review inspectable

ImpactLens addresses the gap between a changed code module and the customer workflows a release reviewer must protect. A file diff alone does not tell a reviewer which business features depend on that file, which tests provide relevant evidence or where coverage is missing. The product combines commit-anchored dependencies, human-confirmed feature mappings, imported CI artifacts and recorded decisions in one review workflow.

The central trade-off was favoring inspectable evidence over automatic certainty. AST extraction is reproducible and avoids executing an imported repository, but it misses some dynamic behavior. Manual confirmation adds work for maintainers, but prevents a name-based suggestion from becoming an unsupported business claim. Frozen comparison inputs consume storage and can retain copies after live artifacts are deleted; they keep historical decisions reproducible. Redis simplifies queues and rate limits, while a database outbox and generation fences preserve publication integrity across restarts.

The controlled commerce evaluation used ten scenarios, four held out, with five measured repeats. Predictions achieved 100% precision and 93.8% recall on that fixture; unsupported dynamic resolution caused one missed feature impact. Broader testing detected that scenario's known failure. All three deliberate bug scenarios were detected in every repeat. The report records per-scenario durations and RSS rather than extrapolating production savings. This small authored corpus is a regression/evaluation tool, not independent proof of market performance.

Operational testing uncovered a conflict between immutable audit rows and repository deletion. The correction preserves the original repository UUID while allowing only the database-managed live foreign key to clear after its parent is removed. It reinforced the need to test deletion against saved reviews and custom database triggers, rather than just mocking repository removal. Restart tests likewise separate job execution from atomic publication and verify that stale workers cannot recreate deleted data.

Packaging adds same-origin routing, explicit proxy trust, production Secure cookies, isolated migration jobs and a Viewer demo with synthetic provenance. The project has not been publicly deployed or tested at production scale. The next useful evidence would be an authorized independent corpus, measured staging recovery and a documented restore rehearsal, rather than a larger unverified savings claim.
