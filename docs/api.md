# HTTP API

All routes use `/api`; Vite and Nginx preserve the prefix. JSON requests use `Content-Type: application/json`. Unknown DTO properties are rejected. UUIDs are full identifiers and commits are lowercase 40/64-character hexadecimal SHAs. [Generated route inventory](api-routes.md) lists every controller path with its authoritative source validator. Shared response contracts live in `packages/shared/src`.

## Authentication and authorization

GET `/api/auth/csrf` sets an anonymous HttpOnly cookie and returns `{csrfToken}`. POST register/login sends that cookie, `Origin: <WEB_ORIGIN>`, `X-CSRF-Token: <csrfToken>` and JSON credentials. Register accepts `{email,password,name}`, login `{email,password}`; passwords are 12–128 characters. Success rotates the cookie and returns `{user,workspaces,csrfToken,expiresAt}`. Use the new CSRF token for subsequent writes. GET `/api/auth/me` returns the identity; POST logout returns 204 and clears the cookie. Production requires HTTPS Secure cookies. No bearer API keys or localStorage tokens exist.

Owner/Engineer/Viewer can read their workspace. Owner/Engineer manage imports, features, artifacts, comparisons and reviews. Owner alone manages members/settings/installations/AI consent and deletes repositories. Every request checks workspace membership and scope; publication checks permissions again. Valid IDs from another workspace cannot be attached.

## Main contracts

Let `W=/api/workspaces/:workspaceId`, `R=W/repositories/:repositoryId`, `C=R/comparisons/:analysisId`. All POST/PATCH/DELETE requests require Origin and session CSRF token.

| Operation                                    | Request / behavior                                                                                                                                                                                                                    |
| -------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------- |
| POST W/repositories                          | `{owner,name}` creates metadata, not GitHub authorization.                                                                                                                                                                            |
| POST W/imports                               | Fixture or authorized GitHub identifiers plus commit/branch; exact union fields in [controller](../apps/api/src/imports/imports.controller.ts). Returns status/progress job; POST cancel/retry follows persisted lifecycle limits.    |
| POST R/snapshots/:snapshotId/graph           | Parse an existing snapshot; no imported code execution. GET graph returns nodes/edges/limitations/evidence. GET files and files/:fileId return retained scoped source.                                                                |
| POST R/features                              | `{name,key?,description?,criticality?,responsibleTeam?,customerWorkflow?}`; PATCH requires `expectedVersion`.                                                                                                                         |
| POST R/features/:featureId/mappings          | `{snapshotId,fileId,nodeId?,rationale}` confirms an anchor; PATCH also needs `expectedVersion`. POST review takes `{expectedVersion,action:"CONFIRM"                                                                                  | "REJECT",snapshotId?}`. Suggestions remain unconfirmed. |
| POST R/test-evidence/artifacts               | `{format,commitSha,runner,recordedAt,filename,source,sourceRoot?,content}`; JUNIT/ISTANBUL/LCOV/PER_TEST, UTF-8 content ≤2 MiB, timestamp with timezone. Returns metadata/hash/parsed evidence; provenance is declared, not attested. |
| POST R/test-evidence/mappings                | `{featureId,artifactId,testIdentity,rationale}` links an imported test identity; DELETE mappings/:mappingId removes the live link.                                                                                                    |
| POST R/comparisons                           | `{baseSnapshotId,headSnapshotId}`; both same-scope snapshots need graphs. Returns saved `id,result,resultHash,inputHash,engineVersion`, SHA pair, semantics/rubric. Frozen source-bearing input stays server-side.                    |
| POST C/reviews                               | `{outcome,comment,expectedRevision,baseSha,headSha,resultHash}`; outcomes in [shared contract](../packages/shared/src/reviews.ts), rationale rules in [Phase 9](phase-9.md). SHA/hash/revision mismatch gives 409. Decisions append.  |
| GET C/report                                 | Saved JSON report with findings, copied evidence, limitations and decision history.                                                                                                                                                   |
| GET/POST C/explanation                       | GET deterministic summary; POST optional AI requires configured provider, consent and budgets.                                                                                                                                        |
| DELETE R/test-evidence/artifacts/:artifactId | Owner/Engineer deletes live artifact/mappings/mirrors; saved comparison copies persist.                                                                                                                                               |
| DELETE R                                     | Owner cancels imports/deletes owned data atomically; original audit repository reference survives.                                                                                                                                    |

GET `/api/health/live` is public; readiness returns 200 only when PostgreSQL/Redis respond, otherwise 503. GitHub callbacks are available only with configured integration. See [Phase 5](phase-5.md), [Phase 6](phase-6.md), [Phase 7](phase-7.md) for detailed graph/mapping/evidence schemas. Controller DTOs document exact bounds for every operation, including workspace membership and legacy draft-analysis routes in the inventory.

Errors use `{error:{code,message,requestId,timestamp}}` with matching `x-request-id`. Statuses: 400 input, 401 session, 403 permission/origin/CSRF, 404 scoped record, 409 stale revision, 413 size bound, 424 import/provider dependency, 429 rate limit, 503 dependencies/capacity. Retry-After is present where applicable; mutations are not universally idempotent. No raw dependency exception/source is logged. Review history uses `?page=1`; comparisons/artifact lists cap at 100/200. Comparisons support ≤200 artifacts and ≤32 MiB frozen input.

For a local GET after demo login, use the browser's same-origin session through DevTools or a private curl cookie jar. Bootstrap CSRF and rotate it after login; never copy production cookies into documentation, screenshots or CI output. Demo credentials are documented in [demo setup](demo.md).
