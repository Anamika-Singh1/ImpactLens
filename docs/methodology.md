# Analysis methodology and limits

1. Capture authorized repository trees at full immutable commit identifiers. Validate archive paths, entry sizes/counts and source text. Preserve file hashes and exclusion/unknown inventory information. Imported code is never executed.
2. Parse supported JavaScript/TypeScript with the TypeScript AST. Extract files, declarations, supported routes and typed import/call relationships. Each relationship retains commit, path and line evidence. Dynamic resolution and unsupported syntax remain explicit limitations.
3. Ask a human to confirm business feature entry points. Lexical suggestions are unconfirmed. Anchors contain declaration fingerprints, file/name/kind and analyzer version. Changes, renames, deletion and ambiguity require review rather than silently remapping.
4. Compare two imported trees (not a PR merge base). Identify changed/deleted/renamed files and walk bounded reverse dependency paths in base and head. Resolve confirmed mappings and report potential feature impact with evidence paths. Business criticality and an explicit rubric determine review priority, not a calibrated failure probability.
5. Import declared JUnit, Istanbul, LCOV or per-test evidence. Validate format, sizes, paths and provenance. Prefer direct per-test evidence and explicit mappings; aggregate coverage does not identify an individual test. Show commit mismatch, age, missing attribution and coverage gaps. Recommend broader testing when evidence is uncertain. Customer tests are never run by the application.
6. Freeze inputs/results and canonical hashes. Append reviewer rationale/outcome against the saved comparison, preserving prior decisions. JSON reports include the saved findings, test concerns and decisions. Optional AI explains existing evidence only; deterministic summaries work without an AI key.

Static reachability is an approximation of runtime behavior. Dynamic imports with computed paths, dependency injection, generated code, reflection, framework conventions, unresolved aliases and external packages can hide relationships or create false positives. Traversal bounds and archive exclusions limit completeness. Mapping quality depends on human domain knowledge. Coverage does not prove business correctness; imported provenance is declared, not cryptographically attested. Saved results preserve the original evidence even after live mappings/artifacts change.

The [measured benchmark](evaluation/report.md) evaluates ten synthetic commerce scenarios, including a four-scenario held-out split, five repeats and known bug tests. Raw feature predictions scored 15 true positives, zero false positives and one missed impact. That miss was unsupported dynamic behavior; broader-test fallback detected its known failure. All three deliberately introduced bug scenarios were detected in every measured run. Those results establish behavior on this fixture only. They do not establish production accuracy, runtime savings, deployment capacity or user adoption.
