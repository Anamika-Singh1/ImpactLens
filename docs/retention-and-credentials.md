# Data retention and credential handling

These are implemented defaults and operator responsibilities, not a claim of compliance certification or production readiness.

| Data                                                                           | Current retention                                                                              | Removal and consequences                                                                                                                                                                                                              |
| ------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Snapshots, retained source, graphs, mappings, saved comparisons and reviews    | Indefinite while their repository exists; no automatic TTL                                     | Owner repository deletion cascades them. Completed comparisons/review history remain immutable until parent removal.                                                                                                                  |
| Imported artifacts, explicit test mappings and mirrored JUnit results          | Indefinite while repository/artifact exists                                                    | Owner/Engineer artifact deletion removes live records. Saved comparisons retain copies; delete the repository to remove those copies.                                                                                                 |
| Audit events                                                                   | Indefinite while workspace exists                                                              | Repository deletion preserves action, actor, timestamp, original repository UUID and opaque target IDs with repository link cleared. Existing workspace removal cascades them. No UI workspace-delete or audit TTL is supplied.       |
| AI explanation cache                                                           | Indefinite while workspace exists                                                              | Consent changes or repository/artifact deletion clear workspace caches. Source analyses remain.                                                                                                                                       |
| AI daily request/token accounting                                              | Indefinite while workspace exists                                                              | Workspace removal cascades it. Deletion does not reset the budget.                                                                                                                                                                    |
| Redis import job payloads                                                      | Completed jobs: one day; failed jobs: seven days, age cleanup applied when queue jobs finalize | Contains DB IDs/generations, not source or credentials. Deleted records make old jobs no-ops. Redis backups may retain older payloads.                                                                                                |
| Sessions                                                                       | Authenticated expiry configured by `SESSION_TTL_HOURS`; anonymous CSRF sessions 15 minutes     | Logout removes the session. Expired sessions cannot authenticate and are cleaned opportunistically on session creation.                                                                                                               |
| OAuth authorization flows                                                      | Ten-minute validity                                                                            | One-use callback deletes the flow; expired/same-session flows are cleaned on starting authorization. No periodic TTL worker is supplied.                                                                                              |
| GitHub user authorization                                                      | Stored AES-256-GCM encrypted, until account removal or explicit server/operator removal        | Expired credentials cannot be used; records are not automatically deleted on expiry. Revoke upstream access through GitHub and remove local authorization records as needed. Repository removal leaves per-user authorization intact. |
| Application logs, database/Redis backups, exported reports, provider-side data | Operator/provider controlled; no application TTL                                               | Set bounded retention and deletion procedures in deployment infrastructure. Deleting application records does not recall downloaded reports, provider submissions or backup copies.                                                   |

Repository and artifact deletion are transactional logical removal from the primary database. They do not promise physical disk erasure: WAL, replicas, backups, already exported files and provider systems can retain copies. Review the operator backup expiry and restore procedure before promising a deletion deadline. A full PostgreSQL backup and Redis backup should be access-controlled and tested for restoration; restoring an older backup can restore previously deleted records unless deletion audit events are replayed according to the operator's policy.

## Secrets

Keep API/worker environment files out of Git. `CREDENTIAL_ENCRYPTION_KEY` is a server-only base64 encoding of 32 random bytes and must match on API and worker. GitHub user tokens use fresh AES-GCM IVs with authenticated ciphertext; wrong keys or tampering fail closed. GitHub App private key/client secret, encryption key and optional AI key never enter browser settings. GitHub installation tokens are short lived and held in memory during archive download. Snapshot exclusion detects common credential filenames/token/private-key patterns heuristically; it is not a general secret scanner.

Use an operator-managed secret store for deployment rather than the example local values. Limit GitHub App installations to intended repositories. Upstream revocation is checked through GitHub requests; a token valid in PostgreSQL is not proof of current upstream access. Rotation of the encryption key requires a controlled migration that decrypts with the old key and reencrypts with the new key, or deleting authorization records and requiring users to reconnect; replacing it alone makes existing ciphertext unreadable. Environment variables can be captured by host/process diagnostics, so restrict operator access and diagnostics collection.

Session cookies contain opaque tokens; only digests are stored in PostgreSQL. Passwords are Argon2id hashes. HTTPS termination and secure cookies (`COOKIE_SECURE=true`) must be configured together with the exact allowed browser origin for an external deployment. The API currently listens on loopback; reverse proxy routing, certificate management, network ACLs, managed DB/Redis authentication, secret rotation, monitoring and backup policy remain deployment responsibilities. Do not put secrets in request IDs: these are accepted trace identifiers and intentionally logged.

AI consent is disabled by default. Explicit provider requests send the minimized evidence projection described in [Phase 8](phase-8.md). Revocation clears local caches and discards in-flight output but cannot recall transmitted data. Provider retention, proxy logs and telemetry must be assessed separately by the operator.
